# HG-RMA302 ロボットの動かし方

Linux PCとUSB接続したXbox 360互換／F310／F710ゲームパッドで、左右の車輪を操作します。**実際に動かすコマンドは `uv run hg-cart drive --config config.local.json --live --log` です。** `--live` を付けない場合は入力と目標速度の表示だけです。

初回は車輪を浮かせ、回転する部分に手や物が触れない状態で試してください。USBとは別に走行用電源が必要です。**Bで両輪停止＋駆動電源OFF、Ctrl-Cで停止してプログラム終了**です。停止は保持ブレーキではありません。

## 1. 初回だけ：環境と機体設定を用意する

リポジトリのディレクトリで実行します。

```bash
uv sync
# 既存の機体設定を上書きせず、なければ作成
cp -n config.robot.example.json config.local.json
uv run hg-cart devices --config config.local.json
```

`config.local.json` はGit管理外なので、clone直後にはありません。従来の `config.example.json` は汎用例で、モーター定数が未設定、電源・IMU統合が無効です。**この機体では `config.robot.example.json` をコピーします。** 設定を省略すると汎用例が使われるため、以下のコマンドでは毎回 `--config config.local.json` を指定します。

この機体用の設定には次を収録しています。別の機体ではUSB固有番号・モーター定数・回転方向を合わせてください。

| 機器 | 識別方法・設定 |
| --- | --- |
| 左ESC | ST-Link `0670FF343433464757213550`、前進符号+1、R=1.887 Ω / L=0.000881 H |
| 右ESC | ST-Link `0665FF535157808667132326`、前進符号−1、R=1.850 Ω / L=0.000930 H |
| 電源Pico | `DE610441238C2E35`、`power.enabled=true` |
| WT61 IMU | `imu.enabled=true`、115200 baud、`yaw_sign=-1` |
| ゲームパッド | 自動検出。今回の接続は `Microsoft X-Box 360 pad` / `045e:028e` |
| 初回の速度設定 | 全体上限・スティック上限30 RPM、加速10 RPM/s、十字キー上下15 RPM・左右8 RPM |
| 電流・電圧 | 各輪Iq上限2 A、始動電流1 A、駆動電圧18〜26 V |
| 始動失敗時 | 自動再試行なし（`observer_retry_limit=0`） |

R/Lは既存の機体記録に基づく値です。ESCはUSB固有番号で探すので、`ttyACM0` などの番号が変わっても左右は入れ替わりません。WT61のCH340には固有番号がないため、設定内の `imu.port` は今回確認したUSB接続位置です。**IMUのUSB差込口を変えたら `/dev/serial/by-path/` を確認し、その設定も更新してください。**

### シリアルポートの権限

`devices` は一覧を表示するだけなので、成功しても通信権限があるとは限りません。`check` 等で「アクセス権限がありません」または `Permission denied` になったら、通常は次を実行してログアウト・再ログインします。

```bash
sudo usermod -aG dialout "$USER"
```

現在のログインのまま試す場合は、`devices` に表示された4つのシリアルポートへ一時的に権限を付けます。以下のポート番号は2026-11-13の接続例です。USB再接続で番号・権限が変わるので、再確認してください。

```bash
sudo setfacl -m "u:$USER:rw" /dev/ttyACM0 /dev/ttyACM1 /dev/ttyACM2 /dev/ttyUSB0
```

ゲームパッドは、このPCのデスクトップログインで読み取り可能でした。見つからない場合はUSB接続を確認し、F310/F710はXInputの **X** 側にします。

## 2. 回転させずに接続を確認する

走行プログラムや他のシリアルモニターを終了してから実行します。

```bash
# 左右ESCの通信、設定、モーター定数、PWM停止を確認。回転指令は送らない
uv run hg-cart check --config config.local.json

# 電源測定を読むだけ。SSR（駆動電源のスイッチ）をON/OFFしない
uv run hg-cart power --config config.local.json --seconds 3

# 機体を静止させ、IMUの受信と校正を確認
uv run hg-cart imu --config config.local.json --seconds 3
```

`check` で `Both ESCs: JSON settings applied and verified` が出れば成功です。USB給電のみでも確認できますが、運転には両ESCで18〜26 Vが必要です。`imu` の `reason` が `IMU_CALIBRATING` から `null` になれば静止校正完了です。

入力だけを調べたい場合は `uv run hg-cart gamepad`、速度への変換も見たい場合は `uv run hg-cart drive --config config.local.json` を使います。終了はCtrl-Cです。**ゲームパッドの入力モニターと走行プログラムは同時に実行できません。**

## 3. 電源を入れて動かす

1. 両スティックを中央へ戻し、十字キーとボタンを離します。
2. 次のコマンドを起動し、機体を約1秒静止させてIMU校正を待ちます。

   ```bash
   uv run hg-cart drive --config config.local.json --live --log
   ```

3. `STOP_LATCHED` と表示されたら、全操作を中立にして **Startを1回押して離します**。これは停止保持の解除です。
4. 駆動電源がOFFなら、**機体の物理電源ボタン**でONにします。Startだけでは電源は入りません。既にONなら押す必要はありません。
5. 全操作を中立にして `READY` を待ちます。左端の `joystick` は操作モードです。
6. 初回は**十字キー上を数秒押し続けます**。両輪が前進方向に回ります。離すと減速して止まります。始動には数秒かかる場合があります。
7. **B**を押すと両輪のPWMを停止し、駆動電源をOFFにして停止を保持します。再開は「中立でStart → 物理電源ボタンON → 中立でREADY」です。
8. 終了するときは **Ctrl-C**。両ESC停止と駆動電源OFFを指示してログを保存します。

時間制限を付けるなら `--seconds 120` などを追加します。時間切れも停止・電源OFFです。診断や終了の後に次の運転を始めるときも、電源と停止保持を確認してください。

## ゲームパッド操作表

起動直後はジョイスティックモードです。LBの保持は不要です。

| 操作 | ジョイスティックモードの動作 |
| --- | --- |
| 左スティック上／下 | 前進／後退。傾きに応じて8〜30 RPM |
| 左スティック左右 | 前後進しながら曲がる。横入力±0.2以内は無効 |
| 右スティック左右 | その場旋回、または前後進に旋回を加える |
| 右スティック上下 | 使用しない |
| 十字キー上／下 | 前進／後退、各輪15 RPM |
| 十字キー左／右 | その場旋回、各輪8 RPM |
| 十字キー斜め | 目標速度ゼロ |
| 全操作を中立 | 減速して停止。次の操作を受け付ける |
| B | 両輪PWM停止＋駆動電源OFF、停止保持 |
| 中立でStart | 停止保持解除。駆動電源はOFFのまま |
| Xboxロゴ／Guide | タンクモードとジョイスティックモードを切替 |

タンクモードでは **左スティック上下＝左輪、右スティック上下＝右輪** です。十字キー・B・Startは共通です。切替後は一度全操作を中立に戻します。Guideボタンがない機種では `drive.control_mode` を `"tank"` または `"joystick"` に設定して起動します。

十字キーを押している間はスティックより優先し、離すとその時点のスティック操作へ戻ります。前進の画面表示は `L=+15 / R=-15` のように右が負になります。左右の取り付け方向を反映した正常な表示です。0〜8 RPMを連続指定することはできません。

## 動かないとき

| 表示・症状 | 対処 |
| --- | --- |
| `DRY RUN` | 表示のみの起動。終了し、`drive ... --live` で起動する |
| `config.local.json` がない | 初回設定のコピー手順を実行する |
| `R/L unset` | 汎用設定を使っていないか確認。この機体用JSONをコピーし、`--config` を指定する |
| アクセス権限エラー | 上のdialout／一時ACLの手順を実行する |
| `USB_ONLY` | USB給電のみ。走行用電源と物理電源ボタンを確認する |
| `WAIT_POWER` | 駆動電源がOFFか電圧不足。バッテリー・配線・物理電源ボタンを確認する |
| `STOP_LATCHED` | 中立でStartを押して離す。その後、物理電源ボタンでONにする |
| `CENTER_CONTROLS` | 左右両スティックの縦横と十字キーを中立に戻す |
| `WAITING_FOR_WHEELS` | 両輪の始動待ち。まず同じ方向を数秒保持する。短い連打や方向変更では加速前に停止する |
| `DPAD_DIAGONAL_STOP` | 十字キーが斜めになっている。いったん離し、上／下／左／右の1方向だけ押す |
| `IMU_CALIBRATING` | 機体を静止させる。動かしている間は校正しない |
| IMUのポートがない・データが古い | USB差込口、`imu.port`、他のモニターの終了を確認する |
| ポート使用中／`Device or resource busy` | 他の `hg-cart`、ゲームパッド／シリアルモニターを終了する |
| `observer_lock` で終了 | 始動推定失敗。車輪の引っ掛かり等を確認。今回の設定は自動再試行しないので、原因を確認して再起動する |
| `no valid response to 'cartcap'` | 停止してUSB・電源を確認。過去には走行電源と両ESCのUSBを外し5秒待つ完全電源断で復旧した。再接続後はまず `check` を実行する |

BやCtrl-C後、通信断後の再開には物理電源ボタンによる電源再投入が必要です。Startを押してもSSRはONになりません。入力・通信・IMU異常では保護停止します。

## ログと詳細資料

`--log` を付けると `artifacts/diagnostics/drive-日時Z.jsonl` に入力、左右ESC状態、電源、IMU、停止理由を保存します。ファイル名の時刻はUTC（日本時間から9時間引いた時刻）です。`RPM_cmd` は目標値で、実際の回転確認にはログの `wheels.*.status.est_mrpm`（RPM×1000）とESC状態、目視を使います。

- [詳細仕様と2026-11-08までの開発記録](docs/technical-reference.md)：ESC設定、停止処理、通信・ファームウェア、過去の試験。
- [2026-11-13の実機確認結果](docs/hardware-check-2026-11-13.md)：今回の設定復元、回転確認、終了後の停止状態。
- [電源Pico・表示パネル](embedded/README.md)：配線、物理ボタン、LED、ビルド手順。

先頭24灯のLEDは待機が青、READYが水色、走行中が緑、停止保持・異常が赤です。末尾6灯はジョイスティックが橙、タンクが水色です。停止保持・異常では全灯赤を優先します。
